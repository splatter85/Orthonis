## Boot and source authority

1. Confirm `splatter85/Orthonis`, the requested branch, and the exact commit. A connector view does not establish the state of an unobserved PC checkout. In a checkout, inspect its own dirty state and preserve concurrent changes.
2. Read [Current Task](docs/CURRENT_TASK.md), the sole live work owner. Follow only the selected scope. Read [Workflow](docs/WORKFLOW.md) for substantive work and publication, then only the owners relevant to that task through [NAV](NAV/README.md).
3. Use [eutonos.read.json](eutonos.read.json) to resolve stable IDs. Read source at the selected revision; do not treat a memory, successful parse, or prior agent's agreement as correctness or authorization.
4. Read [EUTONOS adoption](docs/EUTONOS_ADOPTION.md) before assuming tools or modules exist. This is a repository-files deployment, not an installed local runtime. Do not invoke nonexistent EUTONOS wrappers, fabricate coordinator grants, or claim native RAM/NAV execution.

A direct source read is valid. Do not reload all documentation, rebuild navigation, demand a context packet, or create a campaign for every small edit. Preserve TokenSlang spelling and stable identities; a path move updates the binding, not the identity.

## Record, execute, and finish

For a substantive authorized task, record the scope, input revision, completion criteria, and restart point in the existing work owner before execution. Reuse a standalone slice or campaign when appropriate. Record progress at meaningful boundaries; do not depend on optional memory for recovery.

At closeout, update only changed canonical facts and the compact live checkpoint. Remove completed work from the active selection, keeping its result in the historical owner. An unselected suggested next step must not become an active task. Preserve unresolved work, actual checks, publication state, and what must happen next.

Use the real GitHub expected-version or nonforced branch operation for writes. Never attach an old full tree to a newer parent, force-push, reset another writer's work, or claim a write succeeded without readback. The initial OED1 deployment may publish its bounded documentation/tooling set to `main`; later application work requires its own selected scope and branch policy.

Run the relevant [repository checks](docs/PROJECT_HEALTH.md) before publication. A failed or unavailable check is not a pass. Required document/checkpoint maintenance still applies when optional RAM capture is off or unavailable.

## Product safety boundaries

Orthonis is an investigator with controlled repairs, not an unrestricted elevated chatbot. [Architecture](docs/ARCHITECTURE.md) owns the detailed proposed contract. Preserve these constraints in future implementation:

- Separate inspection, proposal, approval, execution, and verification. Unsupported operations fail closed. Do not execute arbitrary model-returned shell text as administrator.
- Validate a whole plan and its case/source/target preconditions before effects. Log interruptions and partial outcomes honestly. Exact rollback is a property of a specific operation, not a universal promise.
- Treat reports, imported packets, log text, and AI output as untrusted data. The local capability boundary, not a model-provided safety label, grants operations.
- Keep diagnostic evidence local by default. Review and minimize exports. Never silently switch to a paid provider, collect credentials, or claim API access is free.
- Use synthetic data in this public repository. No real machine reports, memory dumps, usernames in captured paths, serial numbers, secrets, private chats, or host-local reservations.

Do not install on or repair a real PC during documentation work. No Windows acceptance, independent-agent comprehension, model savings, or hardware health follows from passing repository checks.

## This deployment's memory and tool boundary

[RAM](RAM/README.md) contains optional public, source-bound Markdown checkpoints. They are not native `ram-record.v1` objects, an execution grant, a second task board, or private reasoning transcripts. Use the checkpoint only when it helps, then inspect current source.

[NAV](NAV/README.md) is a small authored document-routing map, not a generated RNAVL/ATLAS source map. No daemon, dashboard, hook, model delegation, MCP server, hosted workflow, or privileged service is activated by these files. Future runtime adoption must preserve these native owners and record its own target evidence.
