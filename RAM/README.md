# Public repository checkpoints

Document ID: `orthonis.doc.ram-guide`.

This directory is the optional RAM-lite surface of the repository-only EUTONOS workflow: public-safe Markdown checkpoints with stable IDs and exact source routes. These are not native `ram-record.v1` objects, signed runtime receipts, private reasoning, a task queue, or automatic per-turn capture.

## Read

Use a checkpoint when past decisions or an interrupted handoff matter. Its evidence is historical. Resolve the current branch/revision and read the relevant canonical owner before relying on a statement as current. [Current Task](../docs/CURRENT_TASK.md) alone selects work.

[OED1 checkpoint](OED1.md) preserves the initial deployment context. The containing Git commit identifies each checkpoint version; cited source commits identify the evidence it describes. Do not manufacture a future self-referential commit hash.

## Capture and maintain

Capture only a useful material outcome or recovery boundary. Record a stable checkpoint ID, described work ID, author role with its actual attribution limit, event date when known, observed result, exact source commit/path, checks and unknowns. Preserve the original request's scope without copying personal chat history. A same-agent check is not independent comprehension.

Keep goals, architecture, live status, and verification procedures in their canonical owners. A checkpoint links those owners rather than maintaining another editable copy. If a conclusion changes, make an attributable correction and retain the historical source in Git. Do not silently rewrite old evidence as newly observed.

Native RAM installation or migration is separate selected work. It must preserve IDs and provenance rather than relabeling these authored notes as mechanically generated native records. Do not create host identities, signatures, provider usage, timestamps, or capture receipts that were not observed.

Never commit real diagnostics, local usernames/paths, serial numbers, credentials, authentication tokens, private source excerpts, or transcripts. Keep sensitive material outside the public repository even when a local ignore rule would ordinarily hide it.
