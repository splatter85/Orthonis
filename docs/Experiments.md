## EXP-001: GitHub-to-Windows continuity

Question: can a fresh agent recover the goal, active scope, required safety boundaries, source routes, and unrun checks without this kickoff conversation?

Method: use one pinned Orthonis revision with the same available source for a direct-reading baseline and the EUTONOS-routed path. Record correctness, omissions, unnecessary reads, handoff effort, and actual available usage counters. Then inspect a local Windows checkout and return its result through the same owners.

Readiness: needs an authorized fresh session and, for the cross-host portion, an actual Windows checkout. The deploying agent checking its own references is not independent comprehension evidence. No savings are assumed.

## EXP-002: Manual AI investigation loop

Question: does report-and-proposal exchange choose more useful follow-up measurements than a fixed checklist?

Method: use matched synthetic diagnostic cases with known causes and a healthy control, the same initial evidence, a restricted capability catalog, and predeclared diagnostic/false-positive measures. Keep unsupported suggestions and inconclusive results visible.

Readiness: requires a selected and tested report/proposal core. No application code, model call, or credit use is authorized by this entry.

## EXP-003: Controlled repair verification

Question: can a bounded repair demonstrate improvement, detect no improvement, and recover from an interrupted operation without misreporting success?

Method: begin with disposable Windows fixtures and a small reviewed action set. Fix the baseline, comparison procedure, and interruption points before testing. Keep routine system variability and measurement overhead explicit.

Readiness: requires the action contract, execution journal, suitable isolated Windows environment, and separate authorization. Do not run it on an everyday PC as a setup check.
